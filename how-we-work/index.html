02 / Agent

How the agent works on your codebase

A pipeline of specialized agents, each responsible for one stage. A senior QA engineer from our team runs it, reviews the output and decides what goes to your repo.

  1. 01scanDetects your framework, language and what can be tested.
  2. 02mapBuilds a working model of your codebase: critical paths, risk areas, patterns and the tests you already have.
  3. 03researchChecks current docs for your testing stack so tests match today's APIs.
  4. 04analyzeRanks risk and defines the test inventory: how much unit, API, integration and end-to-end.
  5. 05planGroups test cases by feature and decides where each one lives.
  6. 06generateWrites tests, page objects and fixtures that read like your team wrote them.
  7. 07validateRuns four layers of checks and separates real application bugs from test mistakes.
  8. 08deliverOpens a draft pull request with the analysis, the counts and the open questions.

No tests yet

We design the test repository from scratch and deliver a first suite on your critical flows.

Tests that keep breaking

We fix what's broken, standardize the rest and fill the coverage gaps that matter.

A mature suite

Targeted additions only, where coverage is thin. Working tests stay untouched.

Broken locators, fixed with approval

When the UI changes, it re-checks the live page, proposes the fix and waits for a yes before applying it.

Audits with a score

A quality audit of your current tests, gaps between dev and QA repos, and test IDs added to components where they're missing.
